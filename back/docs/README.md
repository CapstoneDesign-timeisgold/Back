# Jiki 백엔드 개발과 운영 안내

<a id="participation"></a>

## 참여 마감과 도착 확인

- 약속 생성 시 참여 마감 설정. 현재 시각보다 늦고 약속 시작 시각 이내로 제한
- 마감 전까지만 초대·수락·거절·참여 취소 허용. 주최자의 마감 변경은 다른 참여자의 첫 수락 전까지만 허용
- 수락한 참여자 본인만 약속 시작 10분 전부터 도착 확인 가능. 서버 확인 시각이 시작 정각까지면 정시, 이후면 지각으로 기록
- 정산 완료 후 참여 상태와 도착 기록 변경 차단

<a id="settlement"></a>

## 정산

- 약속 시작 시각부터 주최자만 정산 요청 가능. 마감 시점에 수락 상태인 참여자만 정산 대상에 포함
- 지각·미확인 참여자에게 벌금 부과. 벌금 합계를 정시 도착자 수로 나눈 뒤 원 단위로 올림하여 지급하고, 초과 지급액은 정산 전용 계정에서 부담. 정시 도착자가 없으면 해당 계정에 벌금 전액 적립
- 약속 행을 먼저 잠그고, 정산에 관여하는 계정 행을 사용자 ID 오름차순으로 잠근 뒤 최신 잔액 조회
- 잔액, 거래 내역, 확정 결과 및 완료 상태를 한 트랜잭션에 저장. 같은 약속으로 다시 요청하면 금액 재반영 없이 204 응답
- 잠금 대기 초과와 데드락 발생 시 롤백 후 새 트랜잭션으로 최대 3회 시도(최초 포함). 모두 실패하면 503 및 `Retry-After: 1` 반환

### DB 적용

- 자동 스키마 변경을 사용하지 않는 환경에서는 배포 전 `back/docs/sql/`의 관련 변경 SQL 적용
- 기존 정산 자금 계정은 운영자가 확인한 사용자 ID로 전환하고 잔액과 거래 내역 유지. 전용 계정의 일반 로그인 및 JWT 인증 차단
- 정산 검증용 DB 설정은 `.github/workflows/backend-tests.yml` 참고. 운영 DB의 정산 제약 점검은 `back/docs/sql/check_settlement_integrity.sql` 사용

## 개선과 검증

- **약속 목록 조회** — 수락 상태 필터와 fetch join 적용으로 약속 100개 조회 시 SQL 202회에서 2회로 감소. 로컬 MariaDB와 k6 동시 사용자 10명 조건에서 3회 측정한 p95 중앙값 58.09ms에서 8.81ms로 감소
- **정산 동시성** — 같은 약속에 동시 요청 10건을 보내도 금액 반영은 한 번으로 유지. 계정을 공유하는 서로 다른 약속을 동시에 정산한 뒤 잔액과 거래 내역 일치 확인
- **잠금 재시도** — MariaDB에서 잠금 대기 초과와 데드락 발생 후 전체 정산 재시도, 재시도 소진 시 503 반환과 변경 사항 롤백 검증. 2026년 11월 16일 기준 일반 테스트 156개 및 MariaDB 테스트 6개 통과

<a id="deployment"></a>

## Nginx 구성

- API 요청은 Nginx에서 Spring Boot로 전달하고, 웹 요청은 Nginx에서 Flutter Web 빌드 파일 제공
- 배포 설정은 `back/deploy/nginx/`에서 관리

## 실험 실행

로컬 MariaDB에 실험 전용 `jiki_perf_*` 스키마와 해당 스키마에만 접근하는 계정을 준비한다. 실험은 이 스키마의 테이블을 생성하고 종료 시 삭제한다. `PERF_DB_URL`에는 `jdbc:mariadb://127.0.0.1:3306/jiki_perf_example` 형태의 주소를 넣고, `PERF_DB_USER`와 `PERF_DB_PASSWORD`를 설정한 뒤 `back/`에서 실행한다.

```sh
./gradlew performanceTest -PperfLabel=after-java -PperfSeconds=10
./gradlew settlementExperiment -PsettlementLabel=after-java
```

- 약속 목록 실험은 SQL 횟수와 HTTP 응답 필드를 검증한다. 동시 사용자 1·10·30명별로 5초 예열 후 3회 측정한다. `docs/performance/results/<label>/`의 `runs.csv`에는 회차별 p95, p99, 처리량과 오류를, `summary.csv`에는 동시 사용자 수별 p95 중앙값·범위와 처리량 중앙값을 기록한다. 변경 전후를 비교할 때는 같은 Java 측정 조건으로 각 버전을 실행하고 요약을 비교한다.
- 정산 실험은 금액 보존과 거래 내역을 검증하고, 동시 사용자 10명이 같은 약속에 총 100회 요청하는 실험을 3회 반복한다. `docs/settlement-experiment/results/<label>/`에 무결성 검증 결과와 HTTP 상태별 집계를 기록한다.
- 두 실험은 회차별 JSON 요약과 압축 CSV 원본을 함께 저장한다. 실행할 때마다 새 라벨을 사용한다. Java HTTP 클라이언트와 서버가 같은 JVM에서 실행되므로 위에 기록된 기존 k6 측정과는 실행 조건이 다르다.
